# 初始化项目文档（三件套）

## Overview

新建开发项目时，统一创建三个 Markdown 文档。三个文件职责互斥、严格分类，同一信息只写一处，其余位置用引用：

| 文件 | 职责 | 回答的问题 | 读者 |
|---|---|---|---|
| `README.md` | **项目熟悉** | 这是什么？为什么存在？怎么跑起来？ | 第一次接触项目的人（含未来的自己） |
| `AGENTS.md` | **开发规范** | 改代码必须遵守什么？ | 所有参与开发的 agent 与人 |
| `DEVELOP_PLAN.md` | **计划与验收** | 做什么？做到哪了？怎么算完成？ | 任务执行者与验收者 |

**Announce at start:** "我正在使用 init-project-docs skill 初始化项目三文档。"

## 内容分类规则（严格归属）

写入任何内容前，先对照下表确定唯一归属文件：

| 内容类型 | 归属 | 示例 |
|---|---|---|
| 项目定位、功能清单、架构概览 | README | "这是一个 XX 系统，包含 A / B 模块"；功能清单是稳定的能力类别快照，不逐功能追加（功能增量进 DEVELOP_PLAN） |
| 环境要求、安装、启动、常用命令 | README | `pnpm install`、`pnpm dev` |
| 技术选型及理由 | README | "用 SQLite，因为单机零依赖" |
| 代码风格、目录约定、命名规范 | AGENTS | "组件放 `src/components/`，PascalCase" |
| 分支 / 提交 / 测试 / 验证流程 | AGENTS | "提交前必须跑 `pnpm test`" |
| 禁止事项、红线 | AGENTS | "禁止直接改 `migrations/` 中已应用的文件" |
| 任务拆解、优先级、状态 | DEVELOP_PLAN | "- [ ] P0: 用户登录接口" |
| 里程碑与时间安排 | DEVELOP_PLAN | "M1（第 1 周）：跑通核心链路" |
| 验收标准（每条可验证） | DEVELOP_PLAN | "输入错误密码返回 401，提示语为 X" |
| 任务执行进度与状态流转 | DEVELOP_PLAN | "- 2026-11-05 执行 完成登录接口，测试 2/3 通过" |

**判断口诀：** 换个人接手项目要看的 → README；改代码要守的 → AGENTS；这件事做完没、对不对 → DEVELOP_PLAN。

## 不冗余原则：引用而非复制

- 同一信息**只允许存在一处**（写在其归属文件中）；其他文档需要时，用相对链接引用，禁止复制粘贴：

  ```markdown
  提交前请先跑测试，流程见 [AGENTS.md · 验证流程](./AGENTS.md#验证流程)。
  环境安装见 [README.md · 安装](./README.md#安装)。
  ```

- 链接用 `./文件名.md#锚点` 精确到小节；锚点为标题原文（空格换 `-`，中文标题直接可用）
- 一条信息在多处出现即视为冗余缺陷：修订时只改归属文件，引用处自动生效
- 临时讨论、单次决策过程不进三文档；结论若需长期遵守，归入 AGENTS；若是任务范畴，归入 DEVELOP_PLAN 对应条目

## AGENTS.md 必建五条（强制）

初始化 `AGENTS.md` 时，无论项目类型，以下五条通用规范**必须写入**「通用规范」小节；可按项目情况追加细节，但不可删减：

| # | 规范 | 执行要求 |
|---|---|---|
| 1 | **复用优先，不过度设计** | 同一逻辑或结构出现**第二份**副本时，立即抽取为公共函数 / 公共样式 / 公共组件；前端页面表现优先组件化；保证代码质量（可读、可测、可维护）；只为已发生的重复做抽象，不为假想的未来需求预先设计 |
| 2 | **文档同步更新** | 分频同步：DEVELOP_PLAN.md 每任务必更（进度追加、状态流转）；AGENTS.md 仅在开发规范变化时更新；README.md 仅在项目定位、结构、用法或环境变化时更新——**新增功能默认只进 DEVELOP_PLAN.md，不逐条追加进 README 功能清单，README 不是变更日志**；文档与代码不同步视为任务未完成 |
| 3 | **计划执行分离** | 动手前先在 DEVELOP_PLAN.md 建任务卡（目标、验收标准、边界）并确认；执行中不得顺手扩范围，需求或范围变化先回任务卡更新，再改代码 |
| 4 | **诚实终态** | 声明完成必须附实际产出文件与验证证据（执行了什么、结果如何）；未运行的测试或验证不得声称通过；受阻时如实标注 blocked 并写明原因与可否绕行 |
| 5 | **精准修改** | 每一行改动都必须能追溯到当前任务；不顺手改进相邻代码、注释或格式，不重构没坏的东西，匹配现有风格；只清理因本次改动产生的孤儿代码（本次改动使其失效的导入 / 变量 / 函数）；发现既有死代码提及而不删，除非任务明确要求；注释只写代码装不下的信息（业务约束、非显然决策、坑位规避），不写修改叙事、阶段引用、代码复述 |

写入 AGENTS.md 时使用以下标准条目（此为唯一权威来源，README / DEVELOP_PLAN 需要提及这五条时一律引用本文件）：

```markdown
## 通用规范（必建五条）

1. **复用优先，不过度设计**：同一逻辑或结构出现第二份副本时，立即抽取为公共函数 / 公共样式 / 公共组件；前端页面表现优先组件化；保证代码质量，不为假想的未来需求预先抽象。
2. **文档同步**：DEVELOP_PLAN.md 随任务同步（进度只追加、状态如实流转）；AGENTS.md 仅在开发规范变化时更新；README.md 仅在项目定位、结构、用法或环境变化时更新——新增功能默认只记录在 DEVELOP_PLAN.md，不逐条追加进 README，README 不是变更日志。文档与代码不同步视为任务未完成。
3. **计划执行分离**：动手前先在 DEVELOP_PLAN.md 建任务卡（目标、验收标准、边界）并确认；执行中不得顺手扩范围，需求或范围变化先回任务卡更新，再改代码。
4. **诚实终态**：声明完成必须附实际产出文件与验证证据（执行了什么、结果如何）；未运行的测试或验证不得声称通过；受阻时如实标注 blocked 并写明原因与可否绕行。
5. **精准修改**：每一行改动都必须能追溯到当前任务；不顺手改进相邻代码、注释或格式，不重构没坏的东西，匹配现有风格；只清理因本次改动产生的孤儿代码（本次改动使其失效的导入 / 变量 / 函数）；发现既有死代码提及而不删，除非任务明确要求。注释只写代码装不下的信息（业务约束、非显然决策、坑位规避），不写修改叙事、阶段引用、代码复述。
```

## 最小骨架

初始化时创建三个文件，只填已知信息，未知项留 `TODO`：

```markdown
<!-- README.md -->
# <项目名>
<一句话定位>
## 功能
- TODO
## 快速开始
<最短可运行路径，通常复制即可跑>
## 环境要求 / 安装 / 启动
<完整细节；小项目可与快速开始合并为一节，避免两节重复>
## 架构概览
（开发规范见 [AGENTS.md](./AGENTS.md)，当前计划见 [DEVELOP_PLAN.md](./DEVELOP_PLAN.md)）
```

```markdown
<!-- AGENTS.md -->
# 开发规范
## 通用规范（必建五条）
<原样写入上方「必建五条」标准条目，不可删减>
## 目录约定
## 代码风格
## 流程要求（分支 / 提交 / 测试 / 验证）
## 禁止事项
（项目背景见 [README.md](./README.md)，勿在此重复）
```

```markdown
<!-- DEVELOP_PLAN.md -->
# 开发计划与验收
## 任务清单
### T1: <任务名>（P0）
- 目标：<一句话说明做什么>
- 动机：<可选，一行为什么做；涉及取舍的任务建议写>
- 验收标准：<可判定的条目，全部满足才算 done；接口 / 交互类任务可用 WHEN/THEN 场景>
- 边界：<明确不做什么，防止顺手扩范围>
- 状态：planned
- 进度（只追加新行，不修改旧行）：
  - YYYY-MM-DD 计划 任务卡确认，验收标准生效
## 状态枚举
| 状态 | 含义 |
|---|---|
| planned | 已建卡确认，未动手 |
| in-progress | 执行中 |
| done | 验收标准全部满足且有验证证据 |
| blocked | 受阻；最新进度行注明原因与可否绕行 |
| canceled | 放弃；最新进度行注明原因 |
## 卡面约定
- **WHEN/THEN 场景写法**（接口 / 交互类任务可选）：
  - WHEN <操作或输入>
  - THEN <可观察的预期结果>
  - 例：WHEN 查询 32 天范围 THEN 返回 400 并提示超出
- **done 卡不删**：完成的任务保留在任务清单中——进度即项目史
- **交付进度行**：阶段为「交付」时，写明实际产出文件与剩余差距（无差距写「无」）

## 里程碑
## 验收清单
（技术背景见 [README.md](./README.md)，改码规则见 [AGENTS.md](./AGENTS.md)，勿在此重复）
```

DEVELOP_PLAN.md 进度行格式：「YYYY-MM-DD 阶段 结果一句话」，阶段取 计划 / 执行 / 验证 / 交付 之一。进度只追加不改写，历史即审计记录（事件溯源思想）；「done 但有剩余工作」时在最新进度行如实说明。

## 执行步骤

1. 按最小骨架创建 `README.md`、`AGENTS.md`、`DEVELOP_PLAN.md`
2. 在 `AGENTS.md`「通用规范」小节原样写入必建五条标准条目
3. 填入当前已知信息，未确定项写 `TODO`，不编造
4. 自检四条：① `AGENTS.md` 包含完整的必建五条；② 逐条核对内容是否写在归属文件（对照分类规则表）；③ 检索是否存在重复内容，有则删掉副本改为引用；④ DEVELOP_PLAN.md 进度区只追加不改写，任务状态值均在枚举内
